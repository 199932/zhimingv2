# 知命V2 Roadmap v2.10 – v3.0

> 战略定位：在已完成「10 功能模块 4 Phase + UX 顺滑化 14 改进 + 自研 fastpatch 工程体系 + 4 套自检/异常/算法修复 Skill」基座上，按 **体验优先** 的优先级倾向，把产品从「功能齐全的原型级占卜工具」打磨成三版递进：
> 1. v2.10「体验打磨版」—— 让人打开就愿意用、用完愿意分享、每日习惯养成；
> 2. v2.11「智能洞察 + 专业加强版」—— 让占卜结果变得「可解释、可复盘、懂你」，并补齐关键算法的专业分支；
> 3. v3.0「完备专业版」—— 基础设施、无障碍、备份安全、节日氛围全补齐，成为一个长期留存、可信可靠的私人命理伴侣。

## Intent Contract（意图契约）

```yaml
intent: 用 3 个连贯版本（v2.10 / v2.11 / v3.0），沿 10 大方向 × 体验优先权重的优先级矩阵，
  逐步把知命V2从"好用工具"进化成"会建议、会复盘、会陪伴、愿意分享"的日常应用；
  全程保持单文件纯前端零联网架构 ≤ 3MB、Chrome 83 WebView 100% 兼容、无外部依赖。
constraints:
  # 工程硬约束（违反即 rollback，不因产品理由让步）
  - single_file: 所有资源、代码、数据、SVG 纹理内置于一个 HTML 文件
  - size_ceiling: 最终每版产物 ≤ 3,145,728 bytes（3 MB）
  - zero_network: 不请求任何第三方 CDN / API / 云端；仅用浏览器原生 API
  - chrome83_compat: 所有新函数声明后立即挂 window；新全局变量用 window._xxx 不用 let/const 顶层延后
  - signature_backward: 不改现有 localStorage key 的旧结构；不改现有函数签名；不删除任何 HTML id/class
  - no_ts: 禁止 TypeScript 标注（as any / : Type），保持纯 ES2019 语法
  # 产品约束
  - no_account: 不引入任何账号/登录体系；身份仅依赖 localStorage
  - privacy_first: 任何"导出/分享"动作默认本地生成，用户主动选择才发送
  - no_gambling: 不出现任何赌博、下注、赔率等内容；所有占卜概率/胜率仅作为个人复盘参考
success_criteria:
  # 量化成功标志（每版发布前要逐项打钩，见各 Phase 的验收段）
  - v2.10: 打开 app → 首次排盘出结果 < 10 秒（真机中端 Android WebView）；
    分享卡可一键保存 PNG 到相册；Hash 直达链接打开后 1 秒内回填表单并出结果；
    成就系统至少 12 枚徽章可点亮
  - v2.11: 奇门飞盘 + 置闰分支全部通过断言（runInlineSelfCheck 新增 QM:feipan / QM:zhirun 2 条）；
    八字子平格局判法对 50+ 常见命例正确；术语 tooltip 覆盖 90% 排盘结果页出现的专业词汇
  - v3.0: 首屏 FCP ≤ 1.2 秒（Chrome DevTools 移动端 3G 模拟下，从空白到 Primary Action Zone 可点击）；
    字号三档 + 繁体 UI + 高对比度 3 项无障碍开关全部真机可切换；
    导出的加密数据文件（密码=test1234）可 1:1 导入恢复
  # 终局感受标志
  - 用户自述："现在这东西，我既愿意自己每天打开抽一张，也愿意发给朋友一起玩一起参考"
risk_level: medium
  - 低风险原因：全部是现有产品的增量层叠（算法加分支/UI 加页面/存储加独立 key），无任何核心推倒
  - 中风险原因：每版 10+ 条改动，需要 fastpatch + 独立 patch 回滚能力；最终 3MB 天花板可能会逼得要做常量分桶惰性挂载（否则 v3.0 爆体积）
```

## Verification Contract（验证契约）

> 对 Initiative 级文档，验证分两层：(1) 本路线图本身结构完整性自审；(2) 每版进入 implementation 阶段时，由该版的 child feature/phase 设计文档各自携带自己的 verification steps，再由 `writing-plans` 生成 workflow 做字节级断言。
>
> 本契约只定义「路线图正确落地」的宏观验收检查。

```yaml
verify_steps:
  # 结构与约束层（本文件产出时立刻检查）
  - structural:
    - check: 10 方向 × 3 版本的优先级矩阵是否齐全、每方向至少 2 条改进项
    - confirm: P0 项目 ≥ v2.10 数量的 70%（体验优先原则），P1 ≥ v2.11 的 70%
    - confirm: 版本边界互斥（同一条改进只出现在一个版本里，不重复）
    - confirm: 所有改进项均不违反 intent 里的 7 条工程硬约束
  # 每版启动前的准备验证（child phase 开工前 gate）
  - per_version_launch:
    - check: 对应版本的 child feature/phase design.md 已产出且含 7 标准段 + 3 契约
    - confirm: 该版预计新增体积估算 ≤ 3MB 减去当前文件体积（估算：JS 常量 1 byte/字 + HTML 节点 30 bytes/个 + CSS 类 20 bytes/条）
    - confirm: 该版新函数列表已列出，数量 ≤ 40 条（保证挂窗 38/42 通过率长期健康）
    - confirm: 旧 localStorage key 零污染（新增 key 都在新列表里列出来了）
  # 版本发布终验（child phase workflow 全部 PASS 后 gate）
  - per_version_release:
    - run: wc -c 知命V2.html ≤ 3MB
    - run: new Function(抽取 script) SyntaxError = 0
    - run: node accel/final_verify.js exit code = 0
    - run: runInlineSelfCheck 中对该版新增的断言条（如 QM:zhirun / DLR:64ke）全部 PASS
    - confirm: 真机（Chrome 83 Android WebView）冒烟一遍「首屏4入口→P0典型排盘→分享/保存→次日打开草稿还在」
```

## Governance Contract（治理契约）

```yaml
approval_gates:
  - G0 [现在]: 本 initiative 路线图整体审阅通过（文件名/版本拆分方向/优先级）
  - G1 [进入 v2.10 前]: v2.10 child phase design + workflow 审阅通过
  - G2 [进入 v2.11 前]: 2.10 已在真机跑 3+ 天、你反馈了体验问题、bug 清零、final_verify 仍 exit=0
  - G3 [进入 v3.0 前]: 2.11 同上；且体积距 3MB 仍剩 ≥ 400KB（否则先做一轮"常量惰性挂载"瘦身再推）
  - G4 [v3.0 发布前]: 做一次全量"回归测试"—— 4 phase 16步 + UX14 所有条目手工点一遍，形成清单回复
rollback:
  - 每个版本的所有改动全部走 `zhiming-v2-fastpatch` 独立 JSON patch 注入；每个版本一份 `patches/v2_10_all.json`、`patches/v2_11_all.json`、`patches/v3_0_all.json`；
    回滚时 revert 对应大 patch 即可（不需手改散点）；每次 apply 前自动做 .backup 备份；回滚直接 cp backup 回来
  - 任何一条改进出现 ReferenceError / TypeError / 体积超 3MB，该条所在版本立刻停止推进，先 fix 再继续
  - 算法改动（如奇门置闰/子平格局）必须配套新增 1-2 条 runInlineSelfCheck 断言；断言不过 = 不算完成
ownership:
  - 产品决策 & 验收 = 你（用户）
  - 方案设计 & 优先级平衡 & 版本拆分 = 我（AI）
  - 具体工程落地 & 代码审查 = hotl:writing-plans + dispatch-agents + 我做集成终验
  - 算法正确性兜底 & 断言编写 = 我（已有 zhiming-v2-algo-selfcheck Skill 作规范）
```

## 1. 问题背景（Problem：为什么现在要做路线图）

### 1.1 现状
经过 v2.9.0 的两轮迭代：
- **模块覆盖已相当全**：中式（八字/奇门/小六壬/周易/梅花/大六壬/紫微/五格/测字）+ 西玄（塔罗/星座/灵数/卢恩）+ 辅助（黄历/节气日历/日记/分享卡/复盘排行榜）共 10+ 排盘、4 类辅助页；
- **工程化基座已打牢**：fastpatch 批处理补丁、final_verify 16步验收、4 套 Skills（iter/error-fix/fastpatch/algo-selfcheck）、异常报告 v2 + 算法自检清单；
- **UX 顺滑化 14 条设计**已产出设计文档：草稿/联动/默认值/快速命令/对比/异常横幅等"操作摩擦"已被系统覆盖。

### 1.2 现有产品的"未完成感"
模块数量已到"够用"的拐点，但真实用户还会遇到的 4 类深层痛点：
1. **看了不会用**：算完八字/奇门，只知道"是什么"，不知道"今天要怎么做、要避开什么、未来30天哪天搬家合适"——**缺具体行动建议层**；
2. **想发发不出**：分享卡做了 3 套主题，但无法直接保存图片、无法生成一条链接直达结果、无法打印成可保存的纸质报告——**缺分享导出层**；
3. **打开没动力**：只有"我有事才来算"的场景，缺少"养成日常打开"的机制（成就/连续签到/每日轮换slogan）——**缺游戏化留存层**；
4. **想学学不会**：术语（七杀/三奇得使/空亡）查词典要跳转，排盘结果页看不懂也不点词典，排盘过程"像是黑盒算出来的"——**缺学习可解释层**。

### 1.3 为什么现在做路线图（不是 feature by feature 零散做）
零散加功能会出现：
- **体积失控风险**：869KB → 每条功能估计 +30–100KB，30 条不规划就会直接撞 3MB 天花板；
- **版本边界模糊**：你不知道"哪些算完了、还剩什么、下一版什么时候能发"；
- **优先级倒置**：有趣但低价值的彩蛋把高价值的"体验打磨"给挤掉了。

## 2. 愿景（Vision：到 v3.0 完成后，知命V2 会是什么）

**一句话愿景：装在手机里的私人命理师 + 学习伴侣 + 生活参考手册，3MB 单文件，离线永远可用。**

拆成 5 条具体体感：

| 编号 | 体感 | 对应哪版先达标 |
|---|---|---|
| V1 | 打开 1 秒就能看到"今天我能做什么"的 4 个按钮 + 一句运势禅语；算完后立刻有"今天别穿红色/谈判别选上午/宜15号签合同" 3 条具体行动建议 | v2.10 达标 |
| V2 | 把排盘结果发给朋友：用一条 Hash 链接打开即出结果；也能存一张好看的 PNG；也能打印一份 3 页的结构化 A4 报告给长辈 | v2.10 达标 |
| V3 | 连用 1 个月：点亮 8 枚成就徽章，获得"初级洞察者"标签；20 个历史条目自动拼成一句话规律："你近期 9/11 的问题都和事业决策有关，星币正逆比=2:7，建议放慢决策速度" | v2.11 达标 |
| V4 | 碰到术语看不懂：点"七杀"弹出定义+例子+你的历史里有哪些命例出现过这个词；点❓看到八字四柱一步步是怎么推出来的 | v2.11 达标 |
| V5 | 给家里老人/色弱朋友用：字号放大 1.5 倍 + 转繁体 + 高对比度配色，一样能顺畅使用；清手机缓存前一键导出加密备份，下次导入 10 秒恢复 | v3.0 达标 |

## 3. 非目标（Non-Goals：这三版里明确不做）

| 编号 | 不做 | 为什么不做 |
|---|---|---|
| NG1 | 账号系统/云同步/云备份 | 违反"零联网、全本地、纯前端"核心定位；隐私争议极大 |
| NG2 | 接入大语言模型 API 做"AI 解卦" | 联网请求；token 消耗 & 费用；依赖稳定性差 |
| NG3 | 拆分成多文件（HTML+JS+CSS 分离或模块打包 Vite/Rollup） | 破坏"单文件拷走即用 + file://直接打开"的最大优势 |
| NG4 | 商城/广告/付费功能（解锁高级卦需要支付） | 纯个人工具定位，商业化会毁掉体验 & 拉低信任 |
| NG5 | 地理位置 API 自动取城市 | 需要联网定位 + 权限授权；localStorage 记住上次城市已经覆盖 95% 场景 |
| NG6 | 相册 OCR 识别身份证填生日 | 需要 tesseract 或视觉模型，单文件塞不下；手工输入错误率已经低 |
| NG7 | 社交聊天/群组/多人同时占卜协作 | 需要服务器端同步；和本项目"单用户私密本地工具"定位冲突 |
| NG8 | 推算法正确性超过权威专业级书籍 | 本工具定位是"日常参考 + 学习工具"，不是国家级易经研究院的标准；95% 场景正确即达标，边缘 5%（如 1813 年节气闰秒、奇门置闰法百年争议分支）UI 说明即可 |

## 4. 利益相关方（Stakeholders）与核心约束

### 4.1 利益相关方

| Stakeholder | 诉求 | 谁负责满足 |
|---|---|---|
| 你（主用户） | 好用、愿意发朋友圈、可长期用、不要变复杂 | 全程你自己 gate approval |
| 家人/朋友（轻量用户） | 字号看得清、繁体字看得懂、操作不超过 3 步 | 由你真机测试后反馈 |
| 初学者（潜在用户画像） | 术语能懂、排盘黑盒不恐惧、有激励让他继续学 | 我在 v2.11 重点设计 |
| 专业用户（你将来可能变成） | 算法分支齐全可切换、结果可复盘、数据导出不失真 | v2.11 / v3.0 重点覆盖 |
| 老手机 / Chrome 83 WebView | 不闪退、首屏不白屏、算法不出错 | 4 套 Skill 终验兜底 |
| 工程可维护性（= 我） | 能按 patch 回滚、体积有预算、新函数挂窗不超 | fastpatch + final_verify 全程守住 |

### 4.2 永远守住的技术约束（和 Intent Contract 对应，便于快速引用）

```
[T1] 单文件 HTML     → 任何资源不外链
[T2] 体积 ≤ 3MB      → 每版剩余容量要记账
[T3] Chrome 83 兼容   → 函数挂 window / 变量不用 let 顶层延后
[T4] 旧签名不破坏     → localStorage key 只加不复用；函数签名不改
[T5] 纯 ES2019 语法   → 禁止 TS/禁止需要 polyfill 的新语法
```

## 5. 架构全景（Architecture Panorama）

### 5.1 10 方向 × 优先级 × 版本归属矩阵

> 标注法：每条改进项后面的（P0/P1/P2）是体验优先权重；`[v2.10]` / `[v2.11]` / `[v3.0]` 表示归属哪一版。**同一方向不同项目可能归属不同版本**，以保证每版都有"立即能感受到的提升"，而不是整版只做一个方向。

| 方向 | v2.10「体验打磨」(P0 桶) | v2.11「智能洞察+专业」(P1 桶) | v3.0「完备专业」(P2 桶) |
|---|---|---|---|
| ① 算法深度 | — | P1 奇门飞盘八门飞布 & 置闰法精确分支；P1 八字子平格局/十神强弱/用神喜忌完整判；P1 大六壬 64 课全课解卦；P1 紫微斗数四化十二宫；P2 周易爻辞动变应期细化 → v2.11 做 4 条，第 5 条应期放 v3 | P2 周易爻辞动变应期细化（承接 v2.11 周易骨架）；P2 测字拆字字形五行推断 |
| ② 结果深度（P0） | P0 每条排盘追加 3 条**具体可执行行动建议**（根据五行+宜忌+方位）；P0 **择日推荐器**（输入"搬家/签约/出差/约会"→未来30天打分排序最佳3天，附理由） | P1 **八字合盘行动指南**（情侣/合作合盘，每个维度1条建议，不只有分数）；P1 **大运流年 SVG 时间轴**（2026-2035 每年一句关键语，横排可滑） | P2 **终身建议 PDF**（结合大运+个人档案，A4 10页结构化可打印） |
| ③ 社交/分享/导出（P0） | P0 **PNG/SVG 保存相册**（canvas 画分享卡→toDataURL→a download 下载）；P0 **Hash 参数化直达链接**（`#/?bazi=张三;1990-1-1;12;男` 打开 1 秒回填表单并计算） | P1 **A4 可打印 PDF 报告**（CSS @page 竖版 3 页结构化排版）；P1 **朋友圈 9 宫切分**（canvas 裁 9 张输出 zip 或逐张保存） | P2 **链接短码**（长 hash 压缩成 12 位短码，映射存 localStorage → 本机能还原） |

### 5.3 每版"体积预算账"（防止撞 3MB 墙）

当前体积 = 869 KB → 3MB 剩余 = 2203 KB。给每版分配预算，超预算必须先做"常量惰性挂载/分桶"瘦身。

| 版本 | 体积预算 | 预估消耗（上限） | 结余（相对当前） |
|---|---|---|---|
| v2.10 | 1000 KB → 最大文件 = 1869 KB | 行动建议规则库 120 + 择日表 100 + 成就数据+图 100 + slogan 20 + canvas/Hash 代码 80 + UI 节点/CSS 180 = 合计 600 KB（保守） | 预算剩 400 KB → 1269 KB |
| v2.11 | 800 KB → 最大文件 = 2069 KB | 算法分支 4 条 250 + 术语词典 tooltip 字典 150 + 可视化帧代码 80 + 规则式总结库 80 + 合盘/大运代码 140 + UI 100 = 合计 800 KB（满打满算）| 精确卡预算；超过 1000KB 就做惰性挂载瘦身 → 瘦身至少省 400KB |
| v3.0 | 余量 1076 KB → 最大文件 = 3145 KB | 性能代码 100 + 无障碍 CSS 变量 + 切换 100 + 简繁映射表 80 + WebCrypto AES 代码 80 + 节气粒子图形库+摇一摇+XP 等级 300 + 数据分桶代码 50 + 彩蛋 80 = 合计 790 KB | 剩 286 KB buffer → 绝对安全 |

> **超预算熔断机制**：v2.11 结束前如果 869 + 600(v2.10) + 800(v2.11) = 2269 KB > 2069 KB（v2.11 预算上限）→ 立刻暂停 v3.0 的任何代码，先做一轮「超大常量惰性挂载」瘦身（TEXT/TAROT_DATA/RUNES_24 延后挂载），该步骤估计可省 400–600 KB，直接把文件拉回 1800 级别内，v3.0 空间恢复。此 gate 写在 Governance 的 G3。

30. `lazy_constants` 超大常量惰性挂载：`TEXT / TEXT.almanac / TAROT_DATA / RUNES_24` 共 4 个超大 JSON/数组，改成 `init()` 里用 `setTimeout(() => { window.TEXT = {...}; paintLazyWidgets(); }, 50)` 延后挂载。首屏 script 解析字节数减少 400–600KB → 直接 FCP 提升。
31. `history_bucket_by_year` localStorage 历史分桶：`saveHistory` 时若年份变更，自动拆 key=`zhiming_v2_history_<YYYY>`；loadHistory 时先读当前年 + 上一年，滚动到底部再加载更早的。读写时间从 O(N) 变 O(当前年份)。
32. `sw_fileuri_fallback` Service Worker file:// 检测降级：在 initPWA 开头加 `if(location.protocol==='file:') return;`；Blob URL 注册失败 try/catch 静默吞掉不抛错。

**(B) 无障碍 & 适老（4 条）**
33. `font_scale_3_levels` 字号三档：top-bar 最右侧加「A」按钮，点击 A→A⁺→A² 三档循环，写入 `document.documentElement.style.setProperty('--fs','1.2')` 存 `zhiming_v2_fs`；所有文字用 `calc(var(--fs,1)*14px)` 做基准。
34. `traditional_ui_toggle` 繁体 UI 切换：在字号按钮旁加「繁」toggle，内置 150 条常用 UI 词映射表（首页→首頁、算八字→算八字 相同保持不动）；算法术语（天干地支/八卦卦名）不转换。
35. `high_contrast_mode` 高对比度模式：`theme-dark` 旁边新开关 `hc` → 给 body 加 `.hc-mode` 类 → 所有装饰渐变变实心、按钮边框加粗到 2px、文字对比度 AA 级（WCAG）。
36. `a11y_48dp_audit` 48dp 热区检查：跑 CSS 注入 `*[onclick], button, .tab-btn { min-width: 48px; min-height: 48px; padding: 8px; }` 的覆盖表；不够的按钮逐个补 padding。

**(C) 备份迁移安全（2 条）**
37. `json_export_import` 个人页「数据」Tab：导出 JSON 按钮 → 下载 `zhiming_backup_YYYYMMDD.json`（含 profiles/history/drafts/diary/liupai/achievements/QC recents 7 大 key）；导入 JSON 按钮 → 选文件后：同 key 同 id 条目冲突 → 弹「覆盖 / 保留旧的 / 都保留（重命名）」3 选 1。
38. `aes_encrypted_export` 加密导出：导出时可选「加密密码保护」→ `window.crypto.subtle.encrypt(AES-CBC, keyFromPw, IV, JSONBytes)` → 下载 `.zhiming` 后缀文件；导入时要求输入密码，密钥错直接拒绝。

**(D) 节日氛围 & 趣味长期留存（3 条）**
39. `jq_24_seasonal_effects` 24 节气动效：init() 内判断今天日期 → 若属于 `{清明/谷雨/小雪/大雪/立春/夏至/秋分}` 中的一个，在 `.primary-action` 背景加 SVG 粒子层（雨滴/雪花/燕子/落叶/阳光射线），粒子数 ≤ 30 不影响 CPU。
40. `shake_random_qiuzan` 摇一摇随机签文：新入口「摇一摇」（top-bar 最右 字号/繁体 旁加「🎲」按钮）→ 启动 DeviceMotion（加速度变化阈值=20），无权限 fallback 连点 6 次；抽到观音灵签 100 签 / 月老灵签 60 签（签文表 160 条 ≤ 20KB），可记入历史 type=qiuzan。
41. `xp_level_system` 占卜等级 XP 系统：每次排盘成功 → XP + 10；复盘标记 → XP + 20；点亮徽章 → + 50；升级阈值 L1=100、每级 ×1.2。当前等级显示在个人页顶部「Lv.N 卜者」，解锁对应配色：L1 米黄（默认）→ L10 墨夜 → L20 霓虹 → L30+ 专属金色边框（只改 CSS 变量）。
42. `zodiac_natal_badge` 生肖本命徽章：档案生肖 + 当前年生肖 → 本命年自动弹「🎖️ 恭喜解锁：生肖·龙 本命徽章」；非本命年但有排盘行为也解锁对应 12 生肖徽章，徽章画廊展示。
