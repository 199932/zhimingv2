- **坑86** Pages 部署队列卡死（push 后 25 分钟不出、last-modified 停旧版）——空 commit kick 两次 3 分钟生效，已成标准动作。

- **坑88** CDN 边缘可能 index 新 / 旧文件交错——关键符号在哪个产物文件就验哪个文件。
- **坑89** python re.search 读真实字节判别，完全绕开 rg 显示层吞字符（坑31 判别法升级版）。

- **坑91** 验证正则按实际分支文案写，断言前先看被测字符串本身。
- **坑92** terser 引号统一（产物断言单引号 0 命中 ≠ 没落盘——先看双引号转写形态再判，假阴性不慌）。
- **坑93** 「注释与实现不一致」是独立债种：SW 注释写 network-first/SWR 实为「缓存命中也 await 一次网络往返」（2026-11-09 外测实锤）——复核代码路径，永远不信注释。
- **坑94** 知识必须在仓库内：账本/build 脚本在仓库外 = agent 每轮开局失忆，修过的 bug 复发（本条即本文件存在的原因）。

**坑138·账本腐烂是元坑**：pitfalls.md 13天零更新期间33个提交里出现城市线5天9提交、弹层层级问题两次复发（坑57写过但没被读到）——「知识在仓库里」只是第一步，坑必须进入迭代回路：每轮交付自查「本轮有没有该记的坑」+修bug前先rg账本关键词。

**坑139·section孤魂**：插入section后必须跑「全section容器归属普查」（找page配对区间+逐section定位归属,28个全绿才算过）——单点验证会漏：sec-cn8漂在page容器外两天，子签高亮但内容空白（switchSec只toggle page内section）。

**坑140·版本号断言污染**：裸版本号count('vX.Y.Z')会被注释/文案污染——v2.142的bump被引擎注释字串骗过跳过,v2.143/144的old串不匹配replace静默无效,线上BUILD停在v2.141三版——版本断言只用「ZHIMING_BUILD = 'vX'」专属前缀串,且先bump后build（terser时值定格）。

**坑141·SW自检强刷副作用**：本地headless验证时unregister SW+caches.clear是必须动作,否则拉旧包假阴性；但线上验证反而要等SW接管（legacy映射等新逻辑只有SW激活后才生效）——本地与线上验证策略相反。

**坑142·城市选择器验收清单**：城市线5天9提交返工密度=验收清单缺失——新弹层/选择器上线必查五件:①容器归属(page内)②z-index走统一通道(不走自开)③叉弹层连带关子弹层+断点续填④搜索词≠数据键(输省名出全省)⑤坐标回填cityName精确优先。

**坑143·审计对账口径**：外测报告数字先实测复核再动手（13天后数字仍全部实锤——但pitfalls时间戳差8小时,总要对一遍）；CI可复现检查必须排除sitemap.xml（lastmod写构建当天,与提交日必然异日,不排除则每次必红）；兼容产物删除=两步（先SW legacy映射上线→隔次部署再删文件）。

**坑142b·文案外置≠函数深拆（防误否）**：坑100量化否决的是Block1函数深拆(617函数长尾/聚类外部引用47~163处)——**拆数据是另一回事**：文案是叶子节点无反向调用,拆出去零耦合成本（TAROT_DATA/词典/解梦表/话术库→assets/data/*.json+__loadData同构加载器）。下一轮agent读到「深拆已否决」不要连带否掉数据外置。量化口径：汉字独占gzip字节=把汉字替换占位符后重gzip的差值（当前212KB/34.9%——压缩包三分之一是写死的文案）。Step2别忘了：紫微/解梦/问命/合参四新模块全在主包,__MOD_URLS自11-09零新增。

**坑144·多步patch中断=后续步骤全未执行**：v2.147.1的patch里剪块assert炸在中段——build.js的MODS条目从未落盘——mod-zh块被build静默丢弃不进任何产物（app假性瘦身36KB,mod清单少一条,看起来一切正常）——**比失败更危险的是"成功的丢失"**。铁律:①多步patch每步独立验证+每步rg读回②产物断言必须逐mod验（ls assets/mod-*清单+__MOD_URLS逐键比对）③patch中断后恢复git基线整套重写,不续跑。
**坑145·write在assert前=脏盘风险**：patch脚本先write后跑断言——断言炸时文件已是坏的——write永远放断言全过后,或write前先在内存态跑完全部assert。
**坑146·文案外置收益递减线**：量化口径(汉字→占位符重gzip差值)两刀实测——自成一体的数据块(CITIES 202KB/紫微解梦群36KB)是甜区,函数级模板散布几十个同步消费点(一页纸/性格四段/流月四段)改造成本指数级——137.8KB剩余汉字里甜区已挖空,继续外置=高风险低收益。合参块23处消费跨boot/switchTab/西玄/八字四区域联动——测量否决,不动。

## 2026-11-25 账本分层日（第7份外测审计）

**坑147·CI的branches字段也会被吞字**：`branches: [main]` 的 `[m` 被显示层吞成 `ain]`（坑31/101同族），YAML仍是合法的（branches解析成on的兄弟key）——workflow照跑但push触发失效+run name显示文件名。判别法：run的name字段显示`.github/workflows/ci.yml`而非`name:`定义值=顶层结构坏。修后必须python yaml.safe_load断言结构。

**坑148·基线截图必须时间冻结**：视觉基线含时段内容（深夜横幅/日期数字/日期哈希分数）=CI任意时间跑必红——mock Date固定（addInit_script FREEZE_JS），基线与时间解耦；连跑两次零差异才算幂等。

**坑149·视觉基线阈值=环境噪声+布局崩的中间地带**：CI与本地字体渲染差2.3~3.3%是环境噪声（fonts-noto-cjk同族仍有hinting差）——阈值5%挡布局崩（白底白字/竖排挤压差异远超5%），低于此值全是假红。

**坑150·patch三连咬的活化石**：①init_script塞进DOMContentLoaded回调尾=JS语法坏但init script抛错不影响页面（静默失效）②python heredoc内嵌三引号=闭合被吞（chr(34)*3拼接避开）③root属主文件rm权限卡（python os.remove绕过）——patch工具链的三类经典死法一次全踩。
